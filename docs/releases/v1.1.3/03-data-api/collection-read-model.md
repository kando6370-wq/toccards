# 收藏分页、摘要与单卡资产读取

本增量记录 2026-11-02 用户体验优化使用的只读接口。原 `/api/v1/collection/dashboard`、`/portfolio/items`、`/wishlist` 继续保留；不修改旧 App 的响应，不新增 schema、migration 或资产写入规则。以下均经过现有 owner 鉴权，以 `owner_type + owner_id` 隔离数据，不能按客户端自报 UID 读取他人资产。

## 单卡资产状态

`GET /api/v1/portfolio/cards/:card_ref/assets` 返回当前账号完整文件夹以及指定卡号的收藏项和心愿项，字段为 `folders/items/wishlist_items`，每项继续使用原 DTO。未收藏的合法卡号返回空资产列表，仍返回当前账号文件夹；不根据目录是否有卡牌推断收藏归属。

新 Flutter 详情页用一次请求取得当前卡的状态，不再为每次打开详情逐页拉取账号的全部收藏与心愿单。卡牌基本资料、行情、图表和收藏／编辑写入接口保持。仅实现原接口的测试仓库继续走原能力路径，实际新客户端需配套提供本接口的 API。

## 分页列表

`GET /api/v1/collection/items` 接受：

| 参数 | 口径 |
|---|---|
| `tab` | `portfolio` 或 `wishlist`，默认 `portfolio` |
| `folder_id` | Portfolio 的目标文件夹，缺省取账号默认文件夹；不允许读取其他 owner 文件夹 |
| `page/page_size` | 默认 1／40，每页上限 100 |
| `sort` | `newest/value_desc/value_asc/change_desc/name_asc/performance_desc`，默认 `newest` |
| `q` | 原名称、系列、展示编号、游戏组成的文本包含匹配，忽略大小写 |
| 重复 `game/language` | 原游戏／语言集合筛选，各类别之间取 AND，同类别内取 OR |
| 重复 `performance_id` | Home 传来的绩效排序优先项，未命中项继续按加入时间排序 |

响应保留 `{success,data}` 包络，`data` 包含 `folders/preference/folder_id/items/total/base_count/page/page_size`。`items` 使用原 dashboard item DTO，`total` 为当前条件的全量匹配条目数，不等于卡牌数量之和；`base_count` 为当前 tab／文件夹未筛选的条目数，用于在不等待价格摘要时区分真实空收藏与筛选无匹配。默认无筛选时直接复用 `total`，不增加一次 COUNT。非法 `tab/sort` 返回 `422 VALIDATION_ERROR`。

默认 `newest` 且没有筛选时，数据库在同一条查询中计算总数与 `LIMIT/OFFSET` 页，只对当前页补卡牌与价格资料。Portfolio 按加入当前文件夹时间倒序，缺失时取创建时间；Wishlist 按创建时间倒序，同值以 ID 稳定排序。

其他筛选／排序模式继续复用原价格匹配和展示规则，对全量结果筛选排序后仅返回请求页；名称比较、缺价排后、合法零价、涨幅和绩效优先项语义保持。比较与筛选使用原客户端 DTO 标准化后的文本含义，不修改历史存储。**这部分减少网络响应与客户端持有数据量，不能宣称已消除服务端全量价格计算。** 后续 SQL 下推或缓存需另行证明与价格维度、历史取值及全部排序等价。

## 全量摘要

`GET /api/v1/collection/summary` 独立返回各文件夹的 `folder_id/item_count/card_count/graded_count/total_value_usd/languages`，以及 `wishlist_count/wishlist_languages/games`。

- `item_count` 是收藏项数，`card_count` 和 `graded_count` 按数量求和；不能用当前列表页替代。
- `total_value_usd` 复用原行情口径乘数量汇总。非空文件夹全部缺价时为 `null`，空文件夹或合法零价为 0；两者不能混同。
- 语言选项来自当前文件夹／全部心愿单，不随已加载页收缩。
- `games` 从当前 owner 已补全的全部收藏／心愿单派生、裁剪首尾空白、去重并排序，不增加 SQL。它保留 `/games` 失败时仍可按已拥有游戏筛选的能力；正常的完整游戏目录优先，不能拿当前页冒充全量游戏选项。
- 摘要保持全量精确计算，并与列表读取分开。普通翻页不要求重复请求摘要；首次摘要和当前页并行可能增加一次重叠计算，不能用首屏更早出现推断数据库总工作已减少。

这些接口仅做本地实现与验证，未发布到 dev/prod。移动端和 API 应配套交付；完整验证、审查及设备边界写入[验证记录](../05-delivery/VERIFICATION.md)。

## 客户端加载与交互

支持分页能力的仓库先读取当前页并在原网格呈现，摘要、目录选项和汇率独立补齐。摘要尚未取得时原统计位置显示 `--`；汇率未知时保留用户币种但金额显示 `--`，不得把 USD 价格冒充目标币种或把未知值当零。成功的空页根据 `base_count` 立即区分空收藏与筛选无匹配，摘要单独失败不覆盖已知的正确空态。

普通翻页追加当前条件的下一页，失败保留已有卡片并原位重试；搜索、筛选、tab 和文件夹变更从第一页重读。整页刷新保留原列表，但刷新期间不并发追加旧条件下一页。账号／页面加载／分页代次分别隔离旧结果；旧文件夹保存失败、旧币种汇率和旧账号摘要均不能覆盖之后的用户选择。

顶部总数、金额和语言来自全量摘要，不从已加载卡片重新求和。游戏目录成功时使用完整目录，目录失败时以摘要中的全部已拥有游戏兜底；筛选弹层保持本地草稿，同时订阅迟到的 Game／语言元数据，关闭后重新打开不是补齐选项的前提。弹层打开期间刷新或退出登录不会读取不可用 dashboard。新建／删除文件夹会同步受影响的摘要与第一页，已失效请求不能把被删除文件夹的数据带回。

未实现分页能力的旧仓库／测试替身保持原全量路径。新路径仍使用相同两列、10px 间距、378px 卡片高度、头部、空态和筛选弹层样式；只在原位置更新加载状态、选项和数据。
