# 查询、缓存与列表性能

更新日期：2026-11-03（Asia/Shanghai）。本文描述本地源码的性能优化及观测口径；不代表 dev/prod 已部署或真实流量验收通过。

## 账号隔离与大收藏读取（2026-11-03）

Home Performance 控制器跟随账号身份变化重置状态并推进请求代次，上一账号的完成／失败不能写入新账号。身份比较使用 owner 类型及账号标识，同一账号正常 token 更新不会清空已加载图表。页面布局、权益门禁和图表范围规则保持。

Search 使用按卡号批量读取的 owner 资产接口，避免为当前卡牌操作等待逐页读取全账号收藏与心愿单；接口和兼容范围见[收藏读模型](../03-data-api/collection-read-model.md#批量卡牌资产状态2026-11-03)。复杂收藏列表先按目标文件夹缩小补全范围，显式语言确定不匹配的条目可提前排除；全量摘要按文件夹预分组。价格排序和摘要仍保留其完整候选集的精确计算，不宣称恒定成本。

图片 variant 继续使用同一源图。2026-11-03 对公开目录三个源图的本机抽样读取分别为 185,183、156,310、37,639 字节，只说明图片大小存在差异，不是移动端首屏、缓存命中率或缩略图收益基准。本轮没有新增缩略图服务、改写源图 URL 或放大图片的质量策略；方案仍须在明确尺寸、服务能力及实际移动端网络数据后确定。

## 请求级观测

共享 API 继续输出一条 `api_request` 完成日志，并沿用 `request_id`、路由模板、HTTP 状态和总耗时。有 PostgreSQL 查询或目录缓存读取时，日志附加 `performance`：

- `sql.count`、`duration_ms`、`max_duration_ms`、`returned_rows`、`errors` 分别表示请求处理期间完成的查询数、客户端累计查询耗时、最慢单次耗时、返回行数和失败次数。
- `sql.statements` 按 SQL 指纹聚合相同指标；指纹为 SQL 去除首尾空白、合并连续空白后 SHA-256 的前 16 个十六进制字符。不记录 SQL 原文、绑定参数、缓存键或搜索词。它用于关联同一查询形状，不是 PostgreSQL 的 `queryid`。
- 每个请求最多保存 20 种指纹，额外查询仍计入总量，并通过 `overflow_count` 记录未展开的次数，防止日志随查询种类无限增大。
- `cache.kv` 记录 Cards 搜索结果 KV 读取的 `hit/miss/error`；`cache.cache_api` 记录行情与价格历史 Cache API 的对应计数。缓存异常与正常未命中分开，两者都继续走既有回源逻辑。未覆盖其他业务的 KV 用法。
- Node/Linux 与 Workers 使用 `AsyncLocalStorage` 隔离并发请求。完成日志只统计前台请求期间已结束的操作；响应结束后才完成的后台任务不补写这条日志。定时任务不借用 HTTP 请求指标。

SQL 时间包含连接排队、网络与驱动处理；并发查询耗时累加可能超过请求总耗时。`returned_rows` 不是扫描行数，既有数据库适配器 `meta.rows_read` 的兼容语义不变。索引效果仍需目标 PostgreSQL 的 `EXPLAIN (ANALYZE, BUFFERS)`，平台支持时结合 `pg_stat_statements`，不能从返回 40 行推断只扫描 40 行。

后续按同接口、相同参数规模、缓存命中状态比较请求 P50/P95、SQL 次数和时间。安装统计与大收藏首页仍需真实负载定位；收藏分页和扫描 Review 的本地优化见下文，真实网络及目标数据库收益仍须单独测量。

2026-11-02 当前开发分支同步既有日志热修：使用 `routePath(context)` 获取实际处理请求的路由。静态 `/cards/search` 与后注册的 `/cards/:card_ref` 同时匹配时，不再用最后匹配项误标搜索请求；请求 ID、日志字段和脱敏规则保持不变。

## 收藏分页与扫描 Review（2026-11-02）

`GET /api/v1/portfolio/items` 在 PostgreSQL 的单条查询中完成账号／文件夹过滤、总数、排序和 `LIMIT/OFFSET`，不再为每页把账号全部收藏传回应用进程。总数与当前页来自同一语句快照，空页也返回总数，不把外连接的空行当作收藏项。请求参数、默认页长、100 条上限、响应包络与账号隔离保持；不新增表或 migration，也不截断仍需要全量数据的收藏首页接口。

用户明确批准将文本排序固定为 PostgreSQL `COLLATE "C"`，避免运行环境语言改变分页顺序。`sort_by` 仍限 `folder_joined_at/created_at/updated_at/card_ref`；缺少加入文件夹时间时仍用创建时间，同值仍按 `id` 升序。大小写、重音及非 ASCII 文本的相对次序可能不同于旧 JavaScript 默认 locale 排序，这是本轮明确批准的排序口径调整。

扫描 Review 的同一 repository 实例共享相同卡号的在途完整加载，后台预加载与打开 Review 重叠时复用详情及行情工作。完成或失败后移除在途记录，后续显式加载仍可获取新价格或重试，不引入长期价格缓存。目录详情和行情请求共用最多 4 个并发名额，等待请求按进入顺序执行，成功和异常均释放名额。

全部 `finish × language` 组合、候选顺序、合法零价及已有部分失败降级规则保持不变；此次不新增批量接口，不改识别、额度或确认入库。受控测试使用 10 张卡、每张 6 个组合验证 70 次必要请求与并发上限，不能换算为真机提速百分比。

## Linux dev 缓存生命周期

Linux 的进程内 KV 为带 TTL 的条目维护一个 60 秒清扫计时器，使用 `unref`，无需再次访问旧键也会回收过期项；没有 TTL 条目后停止计时。读取过期值仍立即返回未命中。

可重建的 TTL 缓存最多保留 10,000 条、约 32 MiB 的 key/value UTF-16 字符估算量，超限先清理过期项，再按最旧写入顺序淘汰；单条超过预算时不保留，且不返回被覆盖的旧值。这是缓存预算，不是 Node 堆内存硬上限，也未包含对象和 metadata 的全部开销。

无 TTL 条目不参与容量淘汰，保留当前唯一的无 TTL 业务键——汇率提供商失败时使用的旧汇率兜底。未来新增无 TTL 业务键时须重新评估容量。Cloudflare prod 的原生 KV 路径不使用该 Map 实现。

## 用户体验与图片加载（2026-11-02 后续增量）

用户要求保持原有页面布局，并明确保留启动固定展示时长及整批扫描结束后才能 Review 的规则。本轮不改卡片尺寸、间距、字体、颜色、按钮位置或首启／Free 订阅页流程；允许内容和加载状态更早在原位置更新。

iOS／Android 卡图按显示区域和设备像素比选择解码档位：常用列表与启动预热共用 512×768 的目标边界，较大显示区域按倍数增加边界。解码保持原图比例、足以覆盖目标区域且不放大小图；该边界不是强制裁剪尺寸，横向或特别狭长的图可能保留更多像素。全屏放大继续请求不限制尺寸的原始解码，缓存键包含解码尺寸，避免放大复用低分辨率图。图片地址、网络源文件和 Web／桌面平台原有路径不变；本轮没有新增缩略图服务、磁盘缓存或图片回填。

启动图片预热跨 Home／Search 批次共用最多 3 个并发名额，同 URL 的在途预热共享一次任务；失败释放名额，离开当前 provider 后不再启动排队图片。原有最多预热 20 张 Search 图、Home 先加载、预热不阻塞启动完成的规则保持。移动端预热与常见列表采用相同解码档位，避免预先解码完整大图后又为列表重复保留不同的大尺寸结果。

移动端图片网络请求使用 25 秒总期限，超时取消原请求并走现有图片失败占位，防止长时间无响应的图片占满预热名额；该期限不包含成功下载后的图片解码。迟到的下载进度不会写入已关闭的进度流。此改动不减少单张图片的下载字节，主要控制解码内存和后台并发，真实网络收益需另行测量。

Search 首屏数据改为 Cards 就绪先显示，Sets 保留独立加载／失败状态。卡图预热监听 Cards 可用状态，不再必须等慢 Sets 的整个初始化 Future 完成；Search 原 `loadComplete` 的完成语义保留。Sets 首批与滚动增量规则见[Cards 与 Sets 说明](../03-data-api/cards-search-order.md#sets-系列列表)。系列详情刷新与卡详情切换材质后的局部重试分别校验请求代次，旧响应不能覆盖当前列表、价格、图表或错误状态。

大收藏的默认列表使用新的分页读接口，单卡详情只读当前卡的 owner 资产；全量统计与复杂价格排序仍保留正确口径，成本边界见[收藏读模型](../03-data-api/collection-read-model.md)。本轮不把摘要全量计算或复杂价序宣称为已完成 SQL 分页，也没有新增数据库缓存或 schema。

## 客户端与后台

- Flutter Search 在一次线性遍历中叠加卡牌覆盖值并筛选，页面构建复用当前标签的可见列表；保持原顺序、收藏覆盖、分页与空态。该改动共用于 iOS/Android，不改变布局。
- 2026-11-02 Flutter Collection 使用 `SliverGrid.builder` 按视口需要构建卡片，并在一次页面构建中复用筛选／排序后的可见列表；原两列、10px 间距、378px 卡高、空态和底部留白保持。该改动减少首屏组件构建量，不代表收藏首页响应已经分页。
- Trending Today 每次刷新创建新的加载代次；旧分页请求无论成功或失败都不能覆盖新榜单、页码或错误状态，刷新后仍可加载新榜单的下一页。现有正涨幅筛选与请求协议不变。
- Admin 扫描列表只查询列表响应使用的字段；`system_result` 仍可用于卡牌类型筛选，但不随列表行传输。详情继续读取完整记录，私有图片路由只读取图片键。
- Admin 列表和详情通过现有 TanStack Query 共享同一 token/path 的在途请求与 Blob。最后一个使用者卸载后不保留缓存，未完成请求可取消；各组件分别创建和撤销自己的 Object URL。继续使用 Bearer 鉴权、401 会话过期通知及 `private, no-store`，没有浏览器持久缓存或公共图片缓存。
- 图片复用减少列表已加载原图后打开详情的重复请求；列表首次加载仍下载原图。生成专用缩略图需要真实图片大小与网络基准，未在本次引入新的图片处理服务、存储格式或回填任务。

Cards 数据库优化见 [Cards 与 Sets 排序及索引](../03-data-api/cards-search-order.md#postgresql-0017-可见卡牌数值排序索引)。本地测试和未验边界见 [验证记录](../05-delivery/VERIFICATION.md)。
