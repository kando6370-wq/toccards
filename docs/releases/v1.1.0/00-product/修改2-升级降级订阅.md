二、订单新增规则

1. 完成JWS验签和解码后，使用signedTransactionInfo.transactionId作为订单唯一键，使用originalTransactionId关联同一条订阅链。

2. 是否新增订单以transactionId为准：

- transactionId尚未存在于订单表：新增一条实际交易记录。
- transactionId已经存在：只能更新已有数据，不能重复新增订单。
- notificationUUID仍用于通知记录去重，不能代替transactionId作为订单唯一键。
- 不能仅根据notificationType、subtype、autoRenewProductId或renewalPrice虚构一条订单。

3. 是否发生成功扣款，需要在新增交易的基础上单独判断：

- 新transactionId且signedTransactionInfo.price大于0：新增订单，并将扣款次数加1。
- 新transactionId但signedTransactionInfo.price等于0：仍然新增试用或免费优惠订单，但不增加扣款次数。
- 没有新transactionId：不新增订单，也不增加扣款次数。
- price缺失时不能使用renewalPrice代替判断本次扣款，也不能增加扣款次数，应记录异常日志并沿用现有交易补查机制。

4. signedTransactionInfo.price是本次交易金额；signedRenewalInfo.renewalPrice只是下一次续订价格，不能写入本次订单金额，也不能用于判断本次是否扣款。

三、升级订阅处理

收到DID_CHANGE_RENEWAL_PREF + UPGRADE时：

1. 解码signedTransactionInfo。

2. 如果transactionId尚未入库，则新增升级订单：

- 订单ID：signedTransactionInfo.transactionId
- 原始交易ID：signedTransactionInfo.originalTransactionId
- SKU：signedTransactionInfo.productId
- 订单时间：signedTransactionInfo.purchaseDate
- 原始金额：signedTransactionInfo.price及currency，金额单位换算沿用现有逻辑
- 金额（USD）：沿用现有汇率换算逻辑
- 订单状态：升级付款；如果当前枚举不存在该状态，则新增
- 当前订阅状态：按照现有状态计算逻辑写入
- 自动续期：根据signedRenewalInfo.autoRenewStatus写入，1显示“是”，0显示“否”
- 环境：根据JWS中的environment写入

3. 如果本次signedTransactionInfo.price大于0，则该订单计入扣款次数。

4. 新订单创建后，它成为该originalTransactionId下的最新订单。升级前旧订单的SKU、金额、订单时间和订单状态都不能被修改。

5. 如果同一个升级通知被重复发送，或者不同通知携带相同transactionId，只保留一条订单，不能重复增加扣款次数。

6. 订单表SKU必须取signedTransactionInfo.productId，不能取signedRenewalInfo.autoRenewProductId。

四、降级订阅处理

收到DID_CHANGE_RENEWAL_PREF + DOWNGRADE时：

1. 该通知只代表用户预约了下一个周期使用的订阅产品。

2. 正常情况下，signedTransactionInfo.transactionId仍是当前已经存在的交易，因此：

- 不新增订单
- 不增加扣款次数
- 不修改当前订单的SKU
- 不修改当前订单金额
- 不把autoRenewProductId写入当前订单SKU

3. 目标SKU继续按照现有逻辑显示在订阅通知记录表中，订单表仍然显示当前实际生效交易的productId。

4. 当前周期结束并成功按降级后的产品续订时，Apple会发送DID_RENEW并产生新的transactionId。此时按照普通续期逻辑新增订单：

- SKU取新的signedTransactionInfo.productId
- 订单状态写“续期付款”
- price大于0时扣款次数加1
- 新订单成为该originalTransactionId下的最新订单

5. 如果降级后的续订失败并收到DID_FAIL_TO_RENEW：

- 不新增订单
- 不增加扣款次数
- 只更新该originalTransactionId下最新订单的当前订阅状态

五、subtype为空的处理

收到DID_CHANGE_RENEWAL_PREF但subtype为空时，不能仅凭该通知新增订单：

- 如果signedTransactionInfo.transactionId已经存在，不新增订单，只按现有规则更新最新订单的订阅相关状态。
- 如果signedTransactionInfo.transactionId确实尚未入库，则把它作为Apple已经存在但本地遗漏的实际交易进行幂等补录。
- 补录订单的SKU仍取signedTransactionInfo.productId。
- 只有signedTransactionInfo.price大于0时才增加扣款次数。
- 不能根据autoRenewProductId创建一条未来订单。

六、最新订单及扣款次数

- 新增升级或续期订单后，该记录成为同一originalTransactionId下的最新订单。
- 最新订单按照signedTransactionInfo.purchaseDate判断，不能按照通知到达时间或transactionId大小判断。
- 后续没有产生新transactionId的通知，只更新最新订单的“当前订阅状态”和“自动续期”，不能修改历史订单的SKU、金额、订单时间及订单状态。
- 只有新增了唯一transactionId且signedTransactionInfo.price大于0时，扣款次数才加1；price等于0、没有新transactionId或收到重复通知时，扣款次数不变。
