# 订阅升级降级订单改动验收说明

## 1. 结论

管理后台 Apple 通知与订单统计已按《修改2-升级降级订阅》完成本地代码修改和自动化验证。本次仅调整周订阅与年订阅之间的订单事实处理，不包含 Lifetime，不修改已完成的通知列表目标 SKU 逻辑，不涉及数据库 Schema 变更。

当前状态：代码和文档已完成，本地自动化验证通过；dev/prod 均已发布。2026-09-07 prod PostgreSQL-only version `934506ae-d433-4a38-ae40-6d07b109d50e` 已承载 100% 流量，Production/Sandbox 两条 Apple 官方 `TEST` 通知均一次验签并处理成功；真实升级、降级、续订失败与扣款事实仍需 Sandbox/TestFlight 实单验收。

## 2. 产品规则落地

| 场景 | 订单处理结果 | SKU 与金额 | 扣款次数 |
|---|---|---|---|
| 周订阅升级为年订阅 | 新 `transactionId` 新增“升级付款”订单 | 取本次 `signedTransactionInfo.productId/price/currency` | 仅 `price > 0` 增加 1 |
| 重复升级通知 | 相同 `transactionId` 不重复建单 | 已有订单事实不被覆盖 | 不重复增加 |
| 年订阅预约降级为周订阅 | `DOWNGRADE` 不建单，只记录下周期目标方案 | 当前年订阅订单 SKU、金额、时间、状态不变 | 不变 |
| 降级后成功续订 | `DID_RENEW` 的新 `transactionId` 新增续期订单 | 取新交易的周订阅 SKU 和本次金额 | 仅 `price > 0` 增加 1 |
| 降级后续订失败 | `DID_FAIL_TO_RENEW` 不建单，只更新购买链当前状态 | 最新实际订单事实不变 | 不变 |
| 新交易价格为 0 | 仍新增试用或免费优惠交易 | 原始金额为 0，不使用续订价代替 | 不增加 |
| 新交易缺少价格 | 仍保留真实交易，记录异常并进入 Apple Server API 校正 | 原始金额和 USD 金额保持未知 | 保持 `null`，不猜测 |
| 方案变更 subtype 为空 | 已有 `transactionId` 不建单；遗漏的新 `transactionId` 幂等补录 | 始终取交易 `productId`，不取 `autoRenewProductId` 建未来订单 | 仅 `price > 0` 增加 1 |

## 3. 环境范围

- 测试环境：`cardx.week`、`cardx.year`。
- 正式环境：`CardAi.weekly`、`CardAi.yearly`。
- Lifetime 和其他 Product ID 继续沿用原逻辑，不纳入本次方案变更建单范围。
- 订单仍以 `store + environment + transactionId` 幂等，购买链仍以 `environment + originalTransactionId` 关联。

## 4. 管理后台表现

- 订单状态新增“升级付款”，可在订单状态筛选中选择。
- 通知列表继续按已验签的 `autoRenewProductId` 展示周/年目标 SKU。
- 订单列表的 SKU、金额和订单时间始终来自实际 `signedTransactionInfo`。
- 最新订单按 `purchaseDate` 排序确定；没有新交易的通知不会改写历史订单事实。
