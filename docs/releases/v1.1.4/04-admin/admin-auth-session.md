# Admin 启动会话校验

## 问题与根因（2026-11-12）

Admin 页面启动时曾直接把 `localStorage` 中的会话当作有效状态，先挂载 `AdminShell`，再等待受保护接口返回 401。过期或已撤销的会话因此会短暂显示内部页面，随后才切换到登录页。

## 当前行为

- 没有持久会话时直接显示登录页。
- 有持久会话时先调用 `/api/v1/admin/auth/refresh`，成功取得新的 `access_token` 后才挂载 `AdminShell`。
- 刷新令牌无效、已撤销、账号不可用或刷新响应缺少有效 `access_token` 时清除本地会话并显示登录页。
- 网络或服务端非认证错误保留原会话，避免短暂服务故障强制退出；后续受保护请求仍沿用既有 401 失效处理。

认证校验期间显示加载状态，不挂载任何后台业务页面。该修复只涉及 Admin 前端启动状态和既有刷新接口，不改变 API、数据库、权限规则或 Flutter 行为。

## 验证

- 修复前新增的启动认证回归测试失败，证明旧逻辑会在校验前允许后台 Shell 挂载。
- 修复后 Admin 测试、TypeScript 类型检查和生产构建通过；独立代码审查确认启动门控、刷新令牌合并、失效会话清理及 StrictMode 清理逻辑均符合预期。
- 本次未执行远程部署、生产登录或真实浏览器回归；线上双 Admin 入口仍需按发布流程分别验收。
