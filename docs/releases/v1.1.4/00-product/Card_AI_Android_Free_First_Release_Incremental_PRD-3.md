## 2. 首版取消订阅及付费限制

### 2.1 移除的展示与流程

对首版实际包含的页面执行以下变更；没有实现的页面无需为执行本需求而新增。

| 位置或行为 | Android 免费首版规则 |
| --- | --- |
| 首次启动、冷启动订阅引导 | 不展示订阅页或订阅大弹窗，不因订阅信息读取而阻断启动 |
| Profile 及其他已有升级入口 | 移除仅用于购买或升级的 Banner、按钮、皇冠及其点击行为；不保留空位 |
| 现有功能触发的订阅拦截 | 取消付费拦截，不跳入无商品的订阅页，不使用“Coming soon”替代可用功能 |
| 购买、Restore、订阅管理、试用开关、套餐价格 | 首版不提供相关入口及交互 |
| Premium 专属或试用宣传 | 删除或调整与免费首版实际开放范围不符的文案 |
| 功能权限等待与失败 | 不要求核验购买权益后才能使用本期免费功能，不展示订阅核验失败造成的功能锁定 |

移除订阅后，原位置的导航和其他操作保持正常；不擅自添加新的商业化入口、广告解锁或奖励任务。

### 2.2 功能开放与扫描次数

1. 首版实际已实现且纳入发布范围的功能直接免费使用。原本仅因 Premium 受限的 Performance、1Y 等能力，仅在首版本身包含该能力时取消拦截；本文件不要求补做尚未实现的能力。
2. Android 不受 iOS 原有“累计免费扫描 10 张”额度限制，不读取或扣减 iOS 扫描额度。移除对应剩余次数、额度用尽和升级提示；本期不新增每日、每周或每月免费额度。iOS 原有免费及订阅规则保持不变。
3. Android 每个扫描批次最多 10 张。当前批次的卡牌必须通过加入收藏夹或删除全部处理完，才允许开始下一批扫描；仅部分卡牌已处理时仍不能开始下一批。该规则同时适用于游客和注册用户，不能通过单张扫描入口绕过。任务防重复等其他既有业务限制继续保留。
4. 免费开放是 Android 首版的产品规则，不向用户伪造 Premium 订单、试用开始、续费或终身会员身份。
5. 已完成的后台订阅页配置继续保留。本期不新增 Android 订阅配置页面、不要求修改现有 iOS 配置。配置变化、配置不可用或迟到结果不得使 Android 首版出现购买入口或重新锁定本期功能。

加入收藏失败的卡牌仍属于未处理状态，不能因点击过收藏按钮就允许开始下一批；删除或收藏成功后按实际剩余待处理卡牌判断。提示沿用“请先处理当前卡牌”的含义，不出现订阅或次数耗尽提示。

## 3. 共用登录身份，双端账号、业务数据及权益隔离

### 3.1 身份与数据规则

1. 采用“共用基础登录身份，分别管理 iOS 和 Android 平台账号及数据空间”的模型。允许使用现有同一个数据库，不要求拆成两个物理数据库；共用数据库或登录身份不代表共用业务数据。
2. 同一邮箱密码或 Google 身份可用于双端身份验证，每端分别判断是否存在有效的平台账号。首次进入另一平台时，完成该端账号开通，建立独立的空数据空间；不会因为 iOS 已有收藏而自动复制到 Android。已删除平台账号的再次使用必须按第 3.4 节重新注册。
3. Apple ID 使用 Gmail 地址，不代表用户已经拥有 Google 登录方式或 Android 平台账号。不同登录方式是否属于同一基础身份，沿用经身份验证的关联规则，不仅凭邮箱文本相同就合并，更不借此同步业务数据。Android 不要求 Apple-only 用户为了迁移 iOS 资产绑定 Google。
4. 同一身份在两端各有一份收藏属于预期行为。两端收藏同一张卡、创建同名文件夹均可分别成功，数量、价格、成本及后续编辑互不影响。
5. 未删除的注册账号在同平台退出重登、换机或重装后，恢复该平台已有数据；换平台使用只进入另一平台自己的数据空间。游客卸载或换机后仍不保证恢复，不能将注册账号的恢复承诺用于游客。
6. 本期不提供跨平台业务数据迁移、同步、合并入口，不承诺未来自动互通。以下规则必须由服务端保证，不能仅通过客户端隐藏另一端数据实现。

| 数据或状态 | 双端处理规则 |
| --- | --- |
| 基础登录身份、已验证邮箱及关联 Google 身份 | 可以共用；身份验证成功不等于已开通或重新注册当前平台账号 |
| 平台账号有效／已删除状态 | 分别管理；本端删号不得导致另一端账号失效 |
| 收藏、Folder、Wishlist、用户填写的价格和成本 | 分别保存，查询、编辑、删除、迁移均限定当前平台 |
| 扫描记录、待处理批次、扫描额度及补偿记录 | 分别管理，Android 不继承或消耗 iOS 免费扫描额度 |
| 货币、隐藏金额、默认文件夹等用户偏好 | 分别保存，不因另一端修改而改变 |
| 估值历史、Portfolio／单卡 Performance | 只使用当前平台的收藏和历史事件计算 |
| Apple 购买、Restore 及订阅状态 | 仅作用于 iOS，Android 不读取其结果来决定免费功能是否可用 |
| Android 免费访问权 | 仅作用于 Android，不将基础身份标为全平台 Premium，不生成虚假购买记录 |
| 公共卡牌目录、卡价等非用户专属数据 | 可以共用；不因用户数据隔离重复建设公共卡库 |

基础身份共用时，密码及身份验证信息的管理范围需要研发核对现有实现并明确界面语义；本端 Delete Account 不得通过删除共享身份或全局封禁的方式实现。

### 3.2 移除 Apple ID 登录方式

1. Android 登录、注册及其他账号入口移除 Apple ID 登录按钮、图标、说明和对应授权流程，不保留占位。
2. Android 首版保留游客、Google 和邮箱登录，沿用其已有流程；移除 Apple ID 登录后，其余入口在原布局内自然排列，不新增替代登录方式。
3. Android 不提供通过 Apple ID 登录或关联账号的入口，也不引导用户先在 iOS 登录以迁移账号；平台独立规则不变。
4. 本项只修改 Android，不删除或改变 iOS 的 Apple ID 登录及已有账号。

### 3.3 增加平台独立说明

在 Android 登录／注册页面显示一条清晰可见的说明，不新增强制确认弹窗，不要求用户重复勾选：

> Your collections and other app data are separate on Android and iOS. Purchases and subscription benefits do not transfer between platforms.

该说明为产品决定，不作为 Google 强制要求。登录方式可以共用，文案不得继续宣称两套完全无关的登录身份。沿用当前页面风格自然换行，不遮挡登录按钮；如现有说明承诺两端数据互通，需要同步替换。后续订阅版本另行在购买位置说明权益适用平台。

### 3.4 删除账号的范围修正

1. 保留 Settings → Delete Account 入口和现有交互结构，删除的是当前平台账号及关联数据，不是只清空收藏。Android 删除只处理 Android；iOS 对应删除只处理 iOS，另一端账号、数据及登录能力保留。
2. 删除当前平台账号后，撤销该账号在本平台所有设备的登录及刷新凭证，清除当前客户端对应的登录状态和业务缓存，回到未登录状态。另一平台会话继续有效，不受影响。
3. 删除成功后，该平台原账号不再可以直接登录。用户再次使用时必须重新注册当前平台账号；邮箱密码用户进入注册流程，不能因共享基础身份还存在就直接登录一个空账号。
4. Google 若使用登录／注册合一入口，身份验证后必须按新用户流程重新注册当前平台账号，建立新的平台账号关系和空数据空间；不能直接恢复旧平台账号。即使基础身份标识仍相同，也不得恢复已删除的收藏、扫描记录或关联历史。
5. 如另一端仍有有效账号，可保留服务该端所需的共享基础身份，但不能将其作为当前平台账号仍有效的依据。研发需确保重新注册不因共享邮箱唯一约束被错误拒绝，也不能借此复活已删除账号。
6. 删除确认说明本端范围、删除不可恢复及重新使用需要注册。Android 删除不影响 iOS 订阅；如涉及 iOS 删号，现有订阅处理及提示由 iOS 原流程负责，不因本次改造被误改。
7. 删除失败或实际结果未确认时，不显示成功；重试不得扩大到另一端。必要保留记录按真实保留规则处理，不向用户承诺删除仍需保留的数据。
8. 本期不新增“删除两个平台全部账号”按钮，不将 Delete Account 改名为 Delete Android Data，也不新增数据导出功能。

### 3.5 游客注册及登录已有账号

1. 游客会话及其资产同样按平台隔离。Android 游客注册新的 Android 平台账号时，只迁移本端游客资产；即使该基础身份已有 iOS 账号，也不能把 Android 游客资产迁入 iOS。
2. 游客登录已经存在且有效的本端账号，沿用经核对的现有产品规则，不新增静默合并。研发需要明确登录前未处理扫描及游客收藏的保留或处理结果，避免未提示的数据丢失；该细节列入第 7 节核对项。
3. 游客注册迁移不得跨平台，也不得重复迁移产生重复收藏。退出、换账号及删号后不得继续显示上一账号缓存的数据。

### 3.6 后端兼容与使用流畅性

1. 平台及数据归属由服务端登录会话确定，客户端不能通过修改平台参数或提交另一端资源 ID 访问另一端数据。读取、写入、删除、统计及后台人工操作均须遵守隔离范围。
2. 已有正式 iOS 账号的收藏、历史数据和 Apple 购买关系必须保留。迁移前核对是否混入 Android 测试数据；不得根据最近登录设备猜测归属，也不得清空或复制到双端。实际存在混入时，由研发根据可核实来源单独处理。
3. 现有 iOS 正式版本必须兼容改造后的后端，登录、原收藏、购买和 Restore 保持正常；不能要求所有 iOS 用户立即升级才能保住原数据或权益。
4. 仅在历史 Android 测试包曾连接正式后端并产生登录凭证时，才检查这些凭证是否可能按旧规则访问 iOS 数据，必要时撤销或重新绑定正确的平台。不存在这种历史情况时，该项不适用；不凭空增加旧 Android 用户迁移需求。
5. Android 启动和核心操作不得等待 Apple 订阅查询、另一端数据加载或双端同步。隔离改造后应对比登录、收藏加载、扫描提交及结果处理的耗时与错误情况，不得出现由额外串行请求导致的明显体验退化。
6. 若技术方案采用 Android 应用或安装验证，需要处理超时、失败和凭证刷新，避免在每次业务操作前重复阻塞验证；失败不得改用 iOS 数据或授予 iOS 权益。具体机制由研发设计，本 PRD 不指定新增某个 SDK 为必做功能。

## 4. 新增外部账号删除申请渠道

App 内已有删号入口继续保留；外部申请沿用已确定的官网方案，与 App 内采用相同的本平台删号规则。

### 4.1 网页内容与申请流程

官网底部提供 Account → Account Setup 入口，页面展示 App 内 Delete Account 的操作截图及简要说明，并提供 Request Deletion by Email。已有页面按此规则核对调整，不另建一套重复入口；截图占位在上线前替换为实际界面。该页公开可访问，并提供用于 Google Play 账号删除网址的直达链接，无需用户重装 App。

网页必须说明：

- Card AI 应用或开发者名称，并清楚标识适用 Android。
- Request Deletion by Email 指向真实可用的客服邮箱，本期采用人工核验与处理，不额外建设表单或自动删号系统。
- 核验账号所需的必要信息，例如注册邮箱、Android 用户 ID；不得要求提供密码。
- 删除的账号及数据范围、实际处理时间、确需保留的数据及原因。
- 明确用户申请删除的平台；Android 申请不影响 iOS，iOS 申请不影响 Android，不仅凭相同邮箱就删除两端。
- 删除成功后，重新使用已删除的平台需要重新注册，原数据不会恢复。

流程：用户打开 Account Setup → 查看本平台删除范围及 App 操作说明 → 通过 Request Deletion by Email 提交申请 → 核验身份及目标平台 → 删除该平台账号与关联数据、撤销该平台会话 → 按实际结果反馈。平台不明确时先补充确认，不扩大删除范围。

### 4.2 异常与运营结果

1. 信息不足或未能确认账号归属时，只要求补充必要资料，不误删其他账号。
2. 不以退出登录、停用或冻结代替删除；不得仅让用户回 App 自行操作。
3. 处理时间、支持邮箱、保留规则必须由团队提供真实值，未确认前不写固定天数或虚构地址。
4. 邮件方式收到申请不等于已删除；反馈区分已收到、需补充信息、已处理及处理失败。

## 5. Android 特有交互差异

只补平台差异，既有拍摄、选图、搜索及编辑的完整流程不在本文重述。

| 场景 | 需要补充或修改的规则 |
| --- | --- |

| 外部网页 | 保留现有 TCGplayer／eBay 入口；无目标 App 时可通过系统支持的网页方式打开；打开失败仍保留原页面并允许重试 |
| 应用评分／商店跳转 | 已有入口改为当前 Android 应用的 Google Play 页面；链接尚未具备有效目标时不跳转 iOS 或其他应用 |
| 键盘与系统区域 | 适配 Android 键盘、状态栏和底部手势区域，主操作可见可点，输入完成后可恢复页面；不新增无关页面改版 |

## 6. 隐私文本与必要披露的增量

1. 保留现有 Privacy Policy／Terms 入口，只更新与 Android 实际情况不一致的内容。
2. 协议说明基础登录身份可以共用，平台账号状态、业务数据和权益分别管理；删除本端账号不影响另一端，重新使用已删除平台需要重新注册。描述本期扫描照片的上传、用途、处理方、保存与删除规则，以及实际启用 SDK 的数据处理；不描述首版未提供功能的数据处理。
3. 首版移除与实际情况不符的订阅、免费试用、自动续费或跨平台权益承诺；可保留准确标识适用平台或未来服务范围的合法条款，不强制重写全部协议。
4. 照片接收方、保留时间、训练用途及 SDK 行为由研发确认后再写，不猜测“立即删除”“不用于训练”或“无第三方共享”。
5. 不预设新增照片上传同意弹窗。只有核对后触发 Google 显著披露及同意要求时，才在首次相关处理前增加可主动接受或取消的披露；未同意不进行该处理，也不影响其他不依赖它的功能。Toast、自动消失或关闭视为同意均不可作为该同意机制。
6. 披露弹窗如确需新增，具体触发位置、范围与文案在事实确认后补入本节；不把可选建议作为本版已确认开发项。
7. Firebase、Mixpanel、Singular 等实际启用 SDK 的行为统计和归因需能区分 Android 与 iOS；本端行为、收藏及 Performance 不混入另一端。Android 免费使用不得上报为购买、试用或订阅收入。广告 ID 用途和数据安全声明以正式包及实际 SDK 行为为依据，不因“无应用内广告”就默认没有归因数据处理。
8. 正式 App 的用户数据传输及第三方 SDK 链路需由研发核验。仅主 API 使用 HTTPS，不能据此声称所有用户数据传输均已加密；未核实的链路保留为上线核对项，不在 PRD 中预填 Data safety 答案。测试环境情况与正式发布包分别记录，正式包不得误连测试明文接口。
