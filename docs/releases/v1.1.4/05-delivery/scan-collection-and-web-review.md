# 扫描复核、收藏搜索、安装明细与官网缓存（2026-11-25）

本次本地整改覆盖五个路径，共享 API 沿用 V1。Android 使用免费首版策略，iOS 使用原订阅策略。两端继续共用活动扫描队列。

| 路径 | 修复前本地证据 | 验收条件 |
|---|---|---|
| 扫描复核 | 单张添加能处理服务端已确认响应，批量添加将相同响应当作失败 | 两端用两张卡复核，已确认和本次成功的卡都移出队列，真正的 SKU 冲突仍留待处理 |
| 安装明细 | 105 条样本的最后 5 条仅接口可读，国家选项来自第一页 | 列表按分组明细翻页，国家选项覆盖所选环境、日期和平台 |
| 官网扫描 | 两份模型运行资源共 27,051,292 字节，静态绑定的缓存头被覆盖 | 生产公开资源支持 ETag 重新验证，预览及错误沿用 no-store |
| 收藏搜索 | 240 张卡仅命中一张，仍为 240 张查询行情 | 最新排序的文字搜索按页补价，保留总数、展示文本和价格排序合同 |
| 复核行情 | 10 张卡、2 种材质、3 种语言产生 10 次详情、60 次行情调用 | 按卡读取可用行情，核对零价、缺价、Raw、评级和历史客户端合同 |

## 修复结果

| 路径 | 行为与本地验证 |
|---|---|
| 扫描确认 | 单张与批量共用服务端“本次扫描已确认”的判定。Android 免费首版和 iOS 订阅策略各验证两种情况。已确认和本次成功的扫描都移出队列。遇到真实重复 SKU 时，仅移出成功项，重复项留在复核页并提示原因。 |
| 安装分析 | 后台按每页 8 行请求。列表的 `total` 是 UID、日期、国家、平台的分组数，`summary.total_installations` 是安装次数。新增只读 `GET /api/v1/admin/analytics/installations/options`，国家选项遵守后台鉴权，并按环境、日期和平台取全。PostgreSQL 样本内 106 次安装对应 105 行，第 14 页末行的安装量为 2。 |
| 官网静态资源 | 正式模式下，公开静态文件的 200 和 304 响应透传 ASSETS 的缓存策略与 ETag。绑定未提供策略时，浏览器下次使用前重新验证。覆盖 ONNX、WASM 的 GET、HEAD 和条件请求，预览、错误响应及发布清单继续使用 `no-store`。 |
| 收藏搜索 | 在当前账号与文件夹范围内，最新排序的文字搜索先在 PostgreSQL 匹配展示名称、卡组、编号及游戏，再给本页补行情。实测 240 张卡中命中 1 张，传给行情查询的卡片数从 240 降到 1。覆盖缺目录、Wishlist、Unicode、字面量通配符、空结果与越界页。价格排序继续按全体候选的行情排序。 |
| 复核行情 | Flutter 复核显式请求 `GET /api/v1/cards/:ref?include=review_prices`。服务端复用详情查询的已发布快照，仅返回材质、语言、评级机构、分数、品相及美元报价。逐组合与旧接口核对了 Raw、PSA 9.5、零价、无匹配及未标注语言的兜底。10 张卡、每张 6 种组合时，详情请求 10 次，额外行情请求从 60 次降为 0，客户端并发上限为 4。 |

空行情数组表示当前没有报价。旧 API 省略行情字段、补充数据格式错误、运营修正改变缺省维度时，客户端沿用逐变体查价。单卡材质与语言超过 100 种组合时，服务端也省略该字段，限制一次公共详情请求的计算量。普通详情、分享及插件调用仍使用原契约。
