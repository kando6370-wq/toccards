# CardScanFox GEO 优化任务清单

## 使用规则

- 每项完成后再勾选。代码、本地验证、正式发布、正式回读和外部动作分别记录。
- “部分完成”不勾选为完成。必须说明剩余范围和证据路径。
- IndexNow 只在正式页面上线并回读后执行。IndexNow 回执不表示 Google 收录、排名或 AI 推荐。
- Jev 用于问题分类、去重和初步路由。产品事实、测试结果、页面状态和最终验收由 Codex 核对。

## P0 产品证据

### GEO-001 实体卡识别基准

- [ ] 建立经许可的实体卡样本集。
- [ ] 覆盖 Pokémon 普通卡、特殊版本、Magic、One Piece、体育卡、语言、卡套、反光、倾斜和模糊。
- [ ] 为每张卡保留独立正确答案，包含游戏、系列、完整编号、语言和版本。
- [ ] 记录 Top 1、Top 3、Exact Printing、失败率、平均耗时和 P95 耗时。
- [ ] 分开记录网页、iOS 和 Android 的版本、设备、网络和测试日期。

调整逻辑。目录图片只能证明目录匹配流程。实体卡准确率必须使用实物、独立正确答案和失败样本。

完成条件。识别页有样本数量、分组、公式、结果表、版本、日期和原始证据路径。

### GEO-002 统一竞品实测

- [ ] 选定相同实体卡和相同设备、光线、距离、角度。
- [ ] 对 CardScanFox、Ludex、Collectr、CollX 和 TCGplayer 记录候选顺序、人工修正、价格、收藏和批量结果。
- [ ] 记录免费方案、保存数量、地区、日期和官方来源。
- [ ] 将资料事实、实测结果和未知项分开。

调整逻辑。功能资料不能证明准确率或排名。统一卡组和统一流程才能支持实测结论。

完成条件。每个对比表都有卡组、日期、设备、结果、失败项和来源。

### GEO-003 平台能力与免费额度

- [ ] 建立 iOS、Android、Web、Chrome 的平台矩阵。
- [ ] 记录登录、扫描额度、批量容量、Portfolio、Wishlist、价格、导出、图片处理和地区限制。
- [ ] 明确 iPhone 10 次成功扫描与其他平台规则的区别。
- [ ] 记录每次平台资料核对的版本和日期。

调整逻辑。平台和免费额度不能用一条总文案概括。用户需要知道限制属于哪台设备和哪项任务。

完成条件。首页、下载、帮助、App 和 Chrome 文案引用同一份已核对矩阵。

## P1 页面与内容

### GEO-004 “最佳”和“免费”决策页

- [ ] 为最佳 AI 扫描器、最佳 Pokémon 扫描器、最佳免费扫描器和价格场景增加条件对照表。
- [ ] 按平台、卡种、免费额度、价格任务和收藏任务给出选择路径。
- [ ] 每个结论绑定官方来源、实测记录或未知状态。
- [ ] 区分 business card 与 trading card 的歧义。

调整逻辑。用户问“最好”时需要选择理由。没有实测时写适用场景，不写总排名。

完成条件。读者看完首屏和对照表后可以选下一步，并能看到限制。

### GEO-005 主题页厚度审计

- [ ] 为 11 个主题页分别记录需求覆盖、首屏交付、HTML 文本、标题聚焦、独有内容和页内闭环。
- [ ] 每页补一个具体案例、检查表或对照表。
- [ ] 检查每条回答脱离其他段落后仍能读懂。
- [ ] 绑定产品事实、官方来源、公开记录或明确示例。

调整逻辑。问题数量不能替代页面厚度。每个主题页需要解决完整任务并提供下一步。

完成条件。每页有可复算的六维审计记录，缺口有正文、来源和验收条件。

### GEO-006 价格数据质量矩阵

- [ ] 按 Pokémon、MTG、One Piece、体育卡和其他品类列出数据来源。
- [ ] 区分挂牌价、成交价、市场指标、Raw 和 Graded。
- [ ] 记录更新频率、延迟、样本窗口、缺价、异常、重复、币种和来源变化。
- [ ] 发布字段示例，包含卡名、系列、编号、语言、Finish、Condition、Grader、Price、Metric、Source、Observed Date。

调整逻辑。已有方法页解释字段，还需要数据覆盖和质量控制。没有统计时写未知。

完成条件。读者能知道价格表示什么，以及什么时候不应该使用它。

### GEO-007 App 和 Chrome 内容入口

- [ ] App 识别结果页链接识别指南、印次核对和价格方法。
- [ ] App 价格页链接价格历史和收藏管理。
- [ ] Chrome 结果页链接网页识别、候选核对和价格字段。
- [ ] No match、错误候选和缺价状态提供恢复路径。

调整逻辑。官网有内容不代表工具用户能找到内容。工具结果需要提供相关下一步。

完成条件。每个工具状态都有可点击指南，不改变原有识别流程。

## P1 外部信任

### GEO-008 真实用户案例

- [ ] 取得授权，记录大收藏的设备、版本、卡组、成功数、修正数、耗时和入库结果。
- [ ] 发布同名不同印次案例，展示候选、纠正、价格确认。
- [ ] 发布 Portfolio、Wishlist、缺价和 Graded 案例。

调整逻辑。商店评论说明体验方向，完整案例才能说明任务结果。未授权前不发布照片或账号信息。

完成条件。每个案例有授权、条件、原始记录、结果和限制。

### GEO-009 商店资料与评论

- [ ] 提交 App Store 和 Google Play 的本地文案。
- [ ] 提交真实扫描、候选确认、价格日期和收藏截图。
- [ ] 提交真实扫描视频并分别回读 iOS、Android。
- [ ] 核对商店名称、描述、截图、视频和平台入口。
- [ ] 使用平台评分组件收集真实评价，不购买或制造评价。

调整逻辑。本地 Fastlane 文件不等于商店更新。商店回读才是完成证据。

完成条件。两家商店公开资料与官网事实一致。

### GEO-010 Reddit、YouTube 和第三方评测

- [ ] 按社区规则参与 Reddit，公开产品身份，不批量发布广告。
- [ ] 联系收藏类 YouTube 频道，允许评测者自行选择结果。
- [ ] 联系独立卡牌媒体，提供测试卡方法和来源表。
- [ ] 记录联系人、链接、披露、条件和发布状态。

调整逻辑。第三方信任必须来自独立体验。联系稿和候选媒体不等于背书。

完成条件。至少有一个公开第三方体验页面或视频，包含测试条件和独立结论。

- [ ] 对 100 条问题分别使用 ChatGPT、Gemini、Perplexity 独立会话。

调整逻辑。网页端批量回答可以帮助写作，不能替代 100 条独立自然推荐实验。

完成条件。每个平台每道问题都有可复现状态。

调整逻辑。IndexNow、HTTP 200 和 sitemap 不能证明收录、排名或 AI 推荐。

完成条件。每个页面有正式版本、回读时间、收录状态和未验证项。
