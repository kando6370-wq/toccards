# CardScanFox 卡牌目录规模与索引

2026-11-07。对应用户要求：按搜索意图写好标题与简介，让有效单卡页面具备 Google 索引条件。此规格和本地代码不代表正式上线、Google 抓取或实际收录。

## 1. 页面任务与文案

| 页面 | 读者任务 | 文案主信息 |
| --- | --- | --- |
| 首页 | 判断产品用途、是否安装 | 卡牌扫描、核对、价格参考、收藏管理。 |
| Scanner/Identifier 功能页 | 选择 App 来识别实体卡 | 明确是 Card AI App 功能，不能暗示网页可以直接扫描。 |
| Price Checker 功能页 | 学习查自己卡牌价值的方法 | 编号、系列、品相和来源口径；与价格目录分工。 |
| 游戏/系列目录 | 找某个游戏或系列的卡表 | 真实游戏/系列名称、覆盖范围、编号和单卡入口。 |
| 单卡详情 | 确认某个具体印次、查看适用参考价 | 实际卡名、完整编号、系列、可用价格、观测日与上下文。 |
| 比较文章 | 比较产品以作选择 | 比较对象、具体工作流、来源日期和未验证范围。 |
| 指南 | 解决识别、估值或收藏问题 | 具体问题、解释与来源；不靠同义词批量复制。 |

46 个已知旧地址保留。元数据由 seo-pages.json 登记，旧 H1 和正文不因标题优化被缩写或替换。单卡用程序按真实字段生成，不给每张卡调用一次模型，也不自动编写虚构故事。

示例规则：`Charizard 4/102 (30C-CC): Price & Card Details | CardScanFox`。简介提及真实系列与价格观测日；没有可用价格时明确说明，缺价本身不取消一个有用身份页的索引资格。没有匹配历史时，简介不承诺趋势。

## 2. 索引资格与发现批次

这两个机制分别控制：

- 索引资格：正式环境、真实已发布数据、稳定 ID、可信卡名、系列、完整编号和公开目录图。审核/撤回记录、已知备用记录和资料不足页不开放索引。有效零价仍是有价。
- 发现批次：sitemap 可先包含部分合格 URL，后续根据服务容量和真实 GSC/日志反馈扩展。其他合格详情并不因没进入首批 sitemap 而自动 noindex。

初次建议先发现约 1,000 页，可指定有完整资料或已有指南关联的卡种/系列，再逐步扩大。默认的稳定 ID 排序不代表搜索热度。这是工程观察批次，不是 Google 上限或搜索量结论。用户目标仍是让所有具备独立价值的有效卡牌页可以被发现和索引。

同一单卡使用稳定 `/cards/{publicCardId}`。原品相、已有评级、价格序列和排序参数不另造可索引页面，使用基础记录的 canonical。不同语言/工艺是否属于独立源记录，要以真实身份为依据；不能把“同名”直接当成同一张卡。

生成器会检查重复 ID、相同身份和标题冲突。有歧义的记录留作核对，不自动重定向或猜测主卡。遗漏资料、冲突数量和标题简介样例进入候选报告。

## 3. 大规模发现文件

- `/sitemap.xml`：sitemap index。
- `/sitemaps/site.xml`：受保护旧页面和已登记栏目。
- `/sitemaps/cards-00001.xml` 等：单卡分片，项目默认每份至多 10,000 条；同时检查字节数。
- 所有 URL 使用正式 origin 和 canonical 路径，不含预览域名、搜索组合、草稿或 Saved。
- 有可信内容修改时间才写 lastmod。未提供时省略；不拿响应生成时间、导出时间或每日构建时间替代全站更新时间。

Google 单份 sitemap 上限为 50,000 URL 或未压缩 50MB。超过后可拆分并由 index 汇总；不是网站只能有 50,000 页。[Google sitemap 规则](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)。

## 4. 无后台的维护流程

1. 新服务用独立只读连接读取现有目录及已发布价格，保持原 App 代码不变。
2. 用显式预算导出，几十万条采用 NDJSON，不在内存里累计全部原始卡牌对象。完整遍历的结束标记缺失、版本改变或预算耗尽时不替换成功文件。
3. 由导出文件生成候选 sitemap。程序做身份/标题冲突检查、稳定选取、网址和大小检查。扩大批次时保留此前仍合格的网址。
4. 构建读取候选文件，校验哈希、主机、路径、条数和大小，再一起发布。输入错误时保留上个完整产物。
5. 正式发布后回读 sitemap、卡牌页、索引头和首 HTML，再按授权提交 Search Console sitemap。普通卡牌页不使用 Google Indexing API。

命令与参数见独立官网及新服务 README。未配置全量源之前，不能把 30 条 review-snapshot 输入冒充生产全库。

## 5. 抓取成本和页面交付

几十万详情走服务端渲染，不生成几十万个部署资源文件。标题、简介、事实、价格上下文、面包屑和关联链接在首个 HTML 中。

公开正式 HTML 使用按 Worker 版本隔离的缓存，并提供 ETag/304。预览、Saved、带身份头或查询参数的请求不进入公共 HTML 缓存。错误页不缓存成成功页。新服务还有独立的只读预算和缓存；首次大范围抓取仍需在真实目标确认容量。

卡种 → 系列 → 单卡及相关印次使用真实链接。sitemap 帮助发现，不能替代可浏览的结构。对筛选 URL 的抓取控制应按实际日志制定；noindex 需要先抓取才能被看到，不能把它当成减少抓取成本的开关。

## 6. 上线后观察与限制

按批次看：已提交与已发现、抓取和响应耗时、服务错误、已收录、重复/canonical 选择、曝光点击，以及商店点击。没有 GSC 时标为未验证，不推断零需求，也不承诺全部收录。

需重点复核“已发现但未编入索引”“已抓取但未编入索引”、重复内容、soft 404 和服务器错误。先辨别数据质量、页面价值、抓取容量和 canonical，再决定补内容、修复或扩大批次。

Google 支持数据库型站点程序化生成准确、可读且具体的简介；不是每张卡都需要人工写或模型生成。[简介规则](https://developers.google.com/search/docs/appearance/snippet)。规模化页面必须给读者提供价值，不能只换卡名并堆安装按钮。[内容政策](https://developers.google.com/search/docs/essentials/spam-policies#scaled-content)。

sitemap 是发现信号，不保证抓取、收录、排名或 AI 引用。[抓取管理](https://developers.google.com/crawling/docs/crawl-budget)、[重复网址规范化](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)。
