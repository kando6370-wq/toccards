## 2026-10-13 订单筛选结果金额汇总

订单统计页在筛选区与订单列表之间展示三项汇总：

- **筛选结果订单数**：当前已生效筛选条件命中的全部订单数，包含退款订单，与列表分页总数一致。
- **订单金额合计（USD）**：仅加总未处于 `refunded` 状态订单的 `amount_usd_micros`；已退款订单不计入，也不再次从该合计扣除。
- **退款金额合计（USD）**：单独加总当前筛选结果中 `business_status = refunded` 的订单 USD 金额。

两项金额与列表复用全部筛选条件、通知确认范围、产品和部署环境限制；不受当前页码、每页条数或 XLSX 导出上限影响。筛选草稿点击“查询”后生效，查询、重置和刷新同步更新汇总。请求加载中或失败时不展示旧汇总金额。

汇总直接使用订单保存的 USD 金额快照，以整数微单位求和后统一格式化显示；不混加不同币种的原始金额，不重新取实时汇率，不将该数值表述为 Apple 扣费后到账收入。退款分类沿用列表的当前业务状态；退款撤销恢复原状态后，该订单重新计入未退款金额，未知状态但已有 USD 金额的订单不作为退款排除。退款订单时间仍沿用已有退款完成时间口径。

缺少 USD 金额的记录不参与加总，并按未退款/退款分别提示缺失笔数。某一类全部金额缺失时显示 `--`；该类没有订单时显示 `$0.00`。合法零金额订单正常计入，混合有值/缺值时显示已知金额的合计并保留缺失提示。

### API 增量

`GET /api/v1/admin/billing/transactions` 保留现有 `items / total / page / page_size`，新增 `summary`：

| 字段 | 类型 | 口径 |
|---|---|---|
| `amount_usd_micros` | number 或 null | 不含退款的 USD 微单位合计 |
| `refunded_amount_usd_micros` | number 或 null | 已退款订单的 USD 微单位合计 |
| `missing_amount_count` | number | 未退款订单中缺失 USD 金额的笔数 |
| `missing_refunded_amount_count` | number | 退款订单中缺失 USD 金额的笔数 |

列表和汇总使用同一筛选构造器；原有数量查询扩展为数量及金额聚合，不新增独立网络请求。订单明细、排序、XLSX 导出和 Admin 鉴权保持原契约。无数据库 schema/migration、App API 或 Flutter 变更。

2026-10-14 已从干净的 `main@ee3f298` 配套发布至 prod API 与 `admin.tcgcard.fun` / `api.tcgcard.fun` 两个 Admin 入口；双入口静态产物及基础 HTTP 已独立验收，真实 Admin 登录态下的订单金额、筛选和页面交互仍待补验。详细版本与边界见 [本版本验证记录](../05-delivery/VERIFICATION.md)。
