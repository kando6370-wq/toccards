## 维护规则

- 开发前先明确需求、影响和验收条件；模型仅用于判断，不用文档占位替代实际实现。
- 新增、变更、移除及验证结果写入本版本相应分类；未变化的事实直接链接原版本。
- 旧版待验事项取得新证据时，在本版本按日期补证并链接原检查点，保留历史结论。
- 文档以实际代码、迁移、运行配置与验证为依据，明确区分本地测试、Git 交付、dev/prod 发布和外部验收。
- 不把执行日志、任务快照、原始导出物或临时诊断素材放入正式文档；部署、推送、迁移和生产写入仍须单独明确授权。
