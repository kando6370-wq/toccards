## 记录规则

- 后续开发资料默认写入 `docs/releases/v1.1.5/`，历史版本按原位归档目录引用。
- 本地验证、CI、dev、prod、商店发布、用户反馈和 Agent 独立验收必须分别标记，未执行项不得写成通过。
- 实现类文档以对应版本的代码、Schema／迁移、运行配置和测试为主证据，并保留检查日期、来源提交和环境边界。
- 行为、Schema、API、配置、架构或运维变化应在同一任务同步相关文档。
- 不在正式 docs 中保存执行日志、任务快照、截图、Secret、Token、私钥或原始生产响应。
- 文档版本、App 版本、API 版本、Git 提交和环境运行版本分别管理；创建 v1.1.5 不代表代码、数据库或环境发生变化。
