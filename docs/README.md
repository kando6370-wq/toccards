2026-10-09 起，当前增量开发入口为 [v1.1.2](releases/v1.1.2/README.md)，新增业务需求和验收范围尚未定义。[v1.1.1](releases/v1.1.1/README.md) 按用户要求原位归档，保留扫描、插件接口、Admin、兼容设计、研究与交付证据；[v1.1.0](releases/v1.1.0/README.md) 继续开发归档，[v1.0.0](releases/v1.0.0/README.md) 继续冻结。归档不等于未完成的设计、外部验收或商店发布已经通过；部署和客户端状态仍以各历史记录标注的日期为准，本次不重新回读环境或变更软件版本。

## 版本目录规范

```text
docs/releases/vX.Y.Z/
  README.md          # 该版本唯一导航入口
  00-product/        # 产品原件，只读
  01-flows/          # 业务流程、角色、状态与规则
  02-architecture/   # 当前架构、工作区、技术栈与决策索引
  03-data-api/       # 数据、API、迁移、契约与技术研究
  04-admin/          # 管理后台实现与权限
  05-delivery/       # 计划、追踪矩阵、配置和发布验收
```

版本可以按实际范围省略空分类；有等价文档时不重复创建另一套结构。

## 维护规则

- `00-product` 保存评审后的原始输入，不随实现修订。
- 已发布历史版本不得回写为后续现状。`docs/releases/v1.0.0` 整体冻结；v1.1.0/v1.1.1 开发记录原位归档，v1.1.2 的新变化不回写旧版本。
- 后续增量写入 `docs/releases/v1.1.2/`；未变化内容直接引用旧版，保留原路径，避免复制整套基线。旧版待验项的新证据在当前版本按日期补证，并链接原记录，不覆盖旧结论。
- 实现类文档以对应版本的代码、Schema/迁移、运行配置和测试为主证据。
- 远程环境、部署和数据规模结论必须保留检查日期；未重新验证时只能作为历史证据。
- 架构建议和选型研究必须标明决策状态，未批准方案不能写成已实施架构。
- 行为、Schema、API、配置、架构或运维变化应在同一任务同步相关文档。
- 执行日志、临时审计、任务快照、失败截图和原始设计导出物不进入正式 `docs/`。
