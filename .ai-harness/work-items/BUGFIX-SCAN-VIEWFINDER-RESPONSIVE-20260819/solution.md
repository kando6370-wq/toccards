# 扫描定位框小屏响应式修复方案

## 根因

扫描页将定位框固定为 `top=213`、`280x400`。可见四角、径向遮罩、扫描线和 OCR 裁剪分别读取这些常量，低高度竖屏中不会为底部 88px 拍照操作区让位。

## 方案

- 保留 `390x844 -> top=213, 280x400` 的 Figma 基准。
- 以 390px 宽、400px 框高为缩放基准，按屏幕可用宽度和顶部/底部控件之间的垂直空间取不大于 1 的连续缩放系数。
- 顶部按免费额度提示存在时的最大控件高度预留，底部按 SafeArea、22px 底边、88px 拍照控件和 20px 间距预留。
- 框保持 0.7 宽高比并水平居中；目标 top 按 `viewport.height * 213 / 844` 计算，再限制在可用垂直区间内。
- 建立单一 `_ScanViewfinderGeometry`，黄色四角、径向遮罩、扫描线和 `_cameraRecognitionCrop` 共用其 `Rect`。
- 装饰尺寸随 scale 缩小但有下限；390x844 基准像素保持不变。

## 边界

- iOS、Android 共用 Flutter 实现，覆盖竖屏手机。
- 大屏框不超过 280x400。
- 不新增 Android 横屏布局，不调整顶部/底部控件。
- 不修改扫描识别、订阅、额度、队列、API 或相机生命周期逻辑。

## 验证

- 先增加 375x667 小屏失败测试，证明旧实现与底部控件重叠。
- 覆盖 320x568、360x640、375x667、390x844、430x932 的框内边界、宽高比和控件间距。
- 验证可见框、遮罩、扫描线和 OCR normalized crop 使用同一矩形。
- 保持现有 390x844 Golden，并新增一个小屏 Golden。
- 运行扫描页定向测试、完整扫描页测试、Flutter analyze、格式和 `git diff --check`。
